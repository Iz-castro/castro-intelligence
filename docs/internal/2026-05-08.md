### 5.7 Bug: `httpx.ReadTimeout` no subscribe_apps

Após wipe, Rafa tentou Embedded Signup pra reonboardar. Modal mostrou
"Unexpected token 'I'..." (frontend tentou parsear "Internal Server
Error" como JSON). Stack: `httpx.ReadTimeout` em `main.py:3006` na
chamada `POST /WABA/subscribed_apps`. Timeout era 15s; código só
tinha proteção pra `status_code >= 400`, deixando exceções de rede
propagarem.

Fix: try/except `httpx.RequestError` + timeout 30s. Canal é criado
mesmo se subscribe falhar (`webhook_subscribed=False`; admin reinscreve
depois). Commit `c632580`. Deploy `00081-2jw`.

### 5.8 Bug: `get_send_credentials` cai em fallback errado

Após signup pós-wipe, Rafa testou enviar mensagem do CRM e recebeu
"Authentication Error". Logs mostram `POST /1070927076104221/messages
→ 401 Unauthorized`. **Phone `1070927076104221` é do canal #4
standard** (do `bootstrap_default_channel` que rodou no startup),
não do canal #1 coex que ele criou.

Causa raiz: Cloud Run tem múltiplas instâncias com cache TTL=60s.
Instance A criou o canal #1 às 19:11; instance B recebeu o
`/api/wa/send` 60s depois com cache stale (sem o canal #1).
`get_channel(1)` → None → fallback `get_default_channel()` → canal
#4 → `WHATSAPP_TOKEN` do Secret Manager (expirado) → 401.

Fix em 2 partes:
1. **Robustez:** quando `channel_id` é explícito e não encontrado no
   cache, fazer **refresh síncrono** do cache e re-tentar antes de
   aceitar o miss. Se ainda assim não achar, levantar `ValueError`
   em vez de cair em outro canal silenciosamente. Falhar fast >>
   enviar pelo canal errado.
2. **Cleanup imediato:** deletar canal #4 + entry phone_routing
   legada `1070927076104221`.

Commit `1fe7379`. Deploy `00082-tm6`.
