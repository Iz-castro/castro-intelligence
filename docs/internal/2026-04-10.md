# 10/04/2026 - Snapshot por visibilidade e rotacao do token WhatsApp

## 1. Problema de permissao no login de operador

### Sintoma
- Usuario novo `administrativo@centralloc.com.br` autenticava normalmente no Firebase.
- Logo apos entrar no CRM, o frontend mostrava alerta de snapshot com `insufficient permissions`.

### Causa raiz
- As `firestore.rules` de `wa_contacts` ja estavam filtrando por visibilidade:
  - admin/supervisor veem tudo
  - operador ve apenas contatos atribuidos a si, sem atribuicao, ou do mesmo departamento
- O frontend ainda abria um `onSnapshot()` da colecao inteira de `wa_contacts`.
- Para operador comum, essa query nao e compativel com as rules e o Firestore derruba a leitura.

### Correcao aplicada
- `frontend/src/context/CrmContext.tsx`
  - snapshot de contatos passou a ser segmentado por visibilidade
  - admin/supervisor continuam com listener unico
  - operador usa listeners separados para:
    - `assigned_to_uid == currentUser`
    - `assigned_to_uid == ""`
    - `assigned_to_uid == null`
    - `department_id == currentUser.department_id`
  - resultados sao mesclados e deduplicados no cliente

### Indices compostos adicionados
- `firestore.indexes.json`
  - `assigned_to_uid + is_archived + last_message_at`
  - `department_id + is_archived + last_message_at`

### Operacao em producao
- Indices publicados no projeto `project-26fb9c99-8ee9-4179-aef`
- Ambos ficaram `READY`

## 2. Problema de envio WhatsApp no canal padrao

### Sintoma
- Mensagens inbound chegavam no CRM normalmente via webhook.
- Ao responder pelo CRM, a Meta retornava `401 Unauthorized`.

### Diagnostico
- Logs do Cloud Run em `POST /api/wa/send`:
  - `Error validating access token: Session has expired on Friday, 10-Apr-26 09:00:00 PDT`
- O ambiente em uso era `Cloud API` padrao, sem coexistence.
- O token expirado estava no secret de producao `castro-crm-whatsapp-token`.

### Validacao
- `debug_token` da Meta confirmou o token antigo como expirado.
- Novo token recebido e validado como:
  - `type = SYSTEM_USER`
  - `is_valid = true`
  - `expires_at = 0`

### Correcao aplicada no codigo
- `channel_service.py`
  - para o canal `standard`, `WHATSAPP_TOKEN` / `WHATSAPP_PHONE_NUMBER_ID` do Cloud Run viraram a fonte de verdade no envio
  - bootstrap do canal default agora sincroniza `access_token`, `phone_number_id` e `waba_id` com as env vars/secrets quando houver divergencia
  - `update_channel()` passou a aceitar atualizacao de `phone_number_id` e `waba_id`

### Operacao em producao
- Secret `castro-crm-whatsapp-token` atualizado no Secret Manager
- Nova versao criada: `version 20`
- Cloud Run reiniciado para recarregar secret novo via:
  - `SECRET_ROTATION_TS`
- Revision final ativa:
  - `castro-crm-00053-9zq`

### Confirmacao no startup
- Log confirmado:
  - `Bootstrap channel: canal default sincronizado com env (id=1 fields=access_token)`
