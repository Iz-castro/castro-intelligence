## 6. Isolamento LGPD (continuação dos `[LGPD]` recentes)

### 6a. Aba "Novos" vazando leads de outros operadores
A aba "Novos" ([CrmContext.tsx:522](../../frontend/src/context/CrmContext.tsx#L522))
filtrava por `conv.assigned_to` (dono do **atendimento**), não por
`contact.assigned_to` (dono do **lead**). Resultado: conversas órfãs de leads já
atribuídos (Helenice, Jaqueline) apareciam em "Novos" das contas admin (e podiam
respingar no pool do operador comum). Fix: "Novos" passa a exigir também
`contact.assigned_to` vazio.
- Commit `ada85eb`. Deploy `castro-crm-00138-pqs`.

### 6b. Fix de origem — conversa herda o dono do lead
Causa das órfãs: `save_wa_message` ([database_firestore.py:1820](../../database_firestore.py#L1820))
criava/tocava a conversa sem propagar o dono → thread nascia órfã
(`assigned_to=None`) mesmo o contato tendo dono. Conversa órfã é legível por
qualquer operador (`firestore.rules` `canSeeContactScoped` libera
`assigned_to_uid==''`). Fix: passa `auto_assign_user_id=contact.assigned_to`; o
guard de órfã em `upsert_wa_conversation` garante que nunca pisa em
transferência/takeover.
- Commit `8d1dd0e`. Deploy `castro-crm-00139-9qx`.

### 6c. Backfill do passivo
`scripts/_backfill_conversation_orphan_owner.py` (idempotente, dry-run, undo
JSON). Aplicado em prod: **168 conversas órfãs** herdaram o dono. Re-dry-run
confirmou convergência (`synced: 0`).

### 6d. PENDENTE — Vetor B (`wa_messages`)
`firestore.rules` para `wa_messages` é `ownsTenant` → **qualquer operador lê
TODAS as mensagens** do tenant via Web SDK. É o maior vetor de leak de PII entre
operadores. Fix exige denormalizar `assigned_to_uid` no doc da mensagem +
ajustar a rule + backfill. **Não mexido hoje.** (Ver [[project-operator-isolation-lgpd]].)

## 7. Conversas duplicadas — causa-raiz (não corrigido)

Sintoma: mesma conversa/mensagem aparecendo 2x. Causa: `save_wa_message` dedup
por `wa_message_id` é **query-then-write não atômico** (doc id é sequence, não o
wamid) → entregas concorrentes/reentregas do mesmo eco criam 2 docs.
Fix recomendado: usar `wa_message_id` como doc id + `create()` atômico. **Não
aplicado.** Nota: o fix 6b adicionou I/O síncrono que pode ter alargado a janela
da race. Prioridade para próxima sessão.
