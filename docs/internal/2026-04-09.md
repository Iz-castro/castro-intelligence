## 1. Assume Counter (feature anterior)
- Previne operadores de acumular contatos assumidos sem resposta
- Contador vai de 0 a -2; bloqueado em -2 ate responder
- Nova colecao Firestore: `operator_assume_counters`
- Frontend: botao "Reset contador" visivel para admin/supervisor

## 2. Notificacoes Sonoras (NOVO)

### Beep de nova mensagem (todos os usuarios)
- Quando total de unread aumenta, toca beep curto (880Hz, 0.3s) via Web Audio API
- Admin pode fazer upload de som personalizado (MP3/WAV/OGG, max 500KB)
- Controlado por `notification_sound_enabled` em system_settings

### Alarme repetitivo (departamentos configurados)
- Alarme dois tons (660/880Hz) toca a cada 30s enquanto houver mensagens nao lidas ha mais de N minutos
- Ativo apenas para operadores dos departamentos selecionados pelo admin
- Para automaticamente quando mensagens sao lidas
- Controlado por: `alarm_enabled`, `alarm_threshold_minutes`, `alarm_department_ids`

### Painel admin (Administracao > Notificacoes)
- Habilitar/desabilitar som de notificacao e alarme separadamente
- Configurar tempo do alarme (1-60 minutos, padrao: 5)
- Selecionar departamentos que recebem alarme
- Upload de som personalizado para notificacao e alarme
- Botoes "Testar" e "Usar padrao"

## 3. Bug Fixes

### Race condition no assume counter (CORRIGIDO)
- `database_firestore.py`: `decrement_assume_counter` e `increment_assume_counter` agora usam `@firestore.transactional`
- Garante atomicidade — dois requests simultaneos nao ultrapassam o limite -2

### Import morto (CORRIGIDO)
- `main.py`: `from firestore_common import document as fs_document, utcnow as fs_utcnow` movido para topo do modulo
- Removidos dois imports locais redundantes dentro de funcoes

### Snapshot sem filtro de visibilidade (CORRIGIDO)
- `firestore.rules`: Regra de `wa_contacts` agora filtra por role:
  - Admin/supervisor: veem todos
  - Operadores: veem contatos atribuidos a si, sem atribuicao, ou do mesmo departamento
  - Usa campo `assigned_to_uid` (ja gravado pelo backend)

## 4. Bot de Atendimento (NOVO)

### Arquivo: `bot_service.py`
Adaptado do `modelo bot.py` para state machine via WhatsApp:
- Estados: `ask_name` -> `ask_equipment` -> `ask_sector` -> done
- Deteccao inteligente: nome, equipamento, setor por numero ou palavra-chave
- Mapeia setores do bot (1-Comercial, 2-Financeiro, 3-Administrativo, 4-SAC) para departamentos do CRM
- Estado armazenado em Firestore: `bot_states/{contact_id}`
- Ao finalizar, grava resumo no contato (`bot_completed`, `bot_setor_nome`, `bot_notes`) e mensagem de sistema

### Integracao no webhook
- `webhook.py`: Apos salvar mensagem inbound de texto, se bot ativo e contato sem operador, processa pelo bot
- Nova funcao `_send_bot_reply()`: envia resposta do bot via WhatsApp API e salva no banco como outbound (operator_name="Bot")

### Frontend
- Nova view "Bot" no NavBar (visivel apenas para admin/supervisor quando bot ativo)
- Contatos no bot (sem `bot_completed`) ficam separados dos "Novos"
- Quando bot finaliza (`bot_completed=true`), contato move para "Novos"
- Quando bot desabilitado, tudo cai direto em "Novos"

### Configuracao admin
- Toggle "Habilitar bot" na aba Sistema do menu Administracao
- Campo `bot_enabled` em system_settings

## 5. Coexistence Liberado para Operadores

### Antes
- Apenas admin podia acessar "WhatsApp Coexistence" no menu
- Endpoints de Embedded Signup restritos a admin/supervisor

### Agora
- Qualquer operador pode acessar "WhatsApp Coexistence" no menu de configuracoes
- Endpoints `/api/admin/embedded-signup/config` e `/exchange` liberados para todos autenticados
- Operador de vendas pode fazer o signup diretamente

## 6. UI: Painel direito (Contato) melhorado

### Cards colapsaveis
- Qualificacao: aberta por padrao
