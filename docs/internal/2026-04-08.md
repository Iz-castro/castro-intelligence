## Objetivo

Evoluir o CRM de numero unico (hardcoded) para arquitetura multi-canal com suporte a Cloud API padrao + coexistence simultaneos, departamentos gerenciaveis, dashboard de auditoria, sistema de avaliacao pos-conversao e reatribuicao em lote.

## Contexto

A empresa contratante nao tinha CRM. Operadores usavam numeros WhatsApp Business pessoais com clientes recorrentes. O sistema precisa de:
- Numero compartilhado (Cloud API) com bot futuro para novos leads
- Multi-numero coexistence para operadores com numeros proprios
- Departamentos com fluxo de transferencia entre setores
- Dashboard de auditoria para Admin/Supervisor
- Sistema de avaliacao pos-conversao (1-10)

### Fase 2: Multi-canal backend

Arquivos modificados:
- `main.py` — todos os 5 endpoints de envio refatorados:
  - `POST /api/wa/send` (texto)
  - `POST /api/wa/send-media` (midia)
  - `POST /api/wa/send-audio` (audio)

  - Novo schema em `wa_contacts`: `channel_id`, `phone_number_id`, `source_channel_type`, `original_operator_id`, `converted_by_user_id`, `rating`, `rating_requested_at`
  - Novo schema em `wa_messages`: `channel_id`, `phone_number_id`, `is_rating_message`, `visibility`
- `main.py` — Embedded Signup atualizado:
  - `EmbeddedSignupExchange` aceita `channel_type`, `owner_user_id`, `label`, `default_department_id`
  - Apos exchange, cria canal automaticamente no registry
