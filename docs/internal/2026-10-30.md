## Base de criação de perfil bloqueada para o editor (pré-existente, corrigido)

Achado anotado na revisão de ontem: criar um perfil novo com a base padrão **Operador** dava 403 para editor de cargo
supervisor com `gerenciar_perfis_acesso` delegado, porque o seed do operador liga `assumir_coex_proprio` e o do supervisor
não — o guard anti-amplificação do `POST /api/admin/perfis-acesso` (`toggles_beyond_user` sobre `SEED_PERFIS[base]`)
recusava o conjunto inteiro, e a UI oferecia as três bases sem trava. Conferido sem Firestore (fallback do seed da role):
editor supervisor → base Operador bloqueada por `assumir_coex_proprio`, base Administrador por 8 chaves, base Supervisor
liberada; editor admin → tudo liberado.

Correção (sem mudar o guard): o `GET /api/admin/perfis-acesso` passou a devolver `bases: [{id, nome, beyond}]`, calculado
com o **mesmo** `toggles_beyond_user` sobre o seed de código (não sobre o doc do tenant, que o admin pode ter editado).
No modal, a opção bloqueada aparece desabilitada ("indisponível para você"), o texto abaixo lista as permissões que
faltam (rótulos do catálogo), o botão Criar fica desabilitado enquanto a base escolhida estiver bloqueada, e a
pré-seleção pula para a primeira base liberada na ordem Operador → Supervisor → Administrador. Fallback para backend
antigo (sem `bases`): as três opções como antes. Tipo `PerfilBaseItem` em `types.ts`.
