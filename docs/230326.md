# Changelog 2026-03-23 — Sprint de melhorias CRM

## 1. Fix: Paginacao de mensagens (50 → 10 + scroll infinito)

**Problema:** O sistema carregava as ultimas 50 mensagens ao clicar num contato, consumindo dados desnecessariamente e nem todas apareciam na tela.

**Solucao:**
- Carga inicial reduzida para **10 mensagens**.
- Ao scrollar para o topo, carrega **+15 mensagens** automaticamente.
- Posicao do scroll e preservada ao carregar mensagens anteriores.
- Indicador visual "Carregando mensagens anteriores..." no topo.
- Backend agora aceita parametro `?limit=N` no endpoint `/api/wa/messages/{contact_id}`.

**Arquivos alterados:** `App.tsx`, `main.py`, `database_firestore.py`

## 3. Nova Feature: Configuracoes do Chat — Prefixo de mensagem

**Descricao:** Dentro de Configuracoes do Sistema > Chat, o atendente pode habilitar/desabilitar o prefixo de mensagem.

**Funcionamento:**
- Toggle habilitado/desabilitado por usuario.
- Quando habilitado, campo para informar o nome que sera usado como prefixo.
- Exemplo: atendente define "Rafael" → mensagem enviada ao cliente: `Rafael: Bom dia, qual martelete voce tem preferencia?`
- O prefixo e aplicado automaticamente no envio, de forma transparente.
- Se desabilitado, a mensagem e enviada normalmente sem prefixo.

**Armazenamento:**
- Preferencia do usuario salva na colecao Firestore `user_settings` (por usuario).
- Configuracao global (habilitado por padrao ou nao) salva em `system_settings`.

**Arquivos alterados:** `App.tsx`, `styles.css`, `database_firestore.py`, `main.py`

## 4. Nova Feature: Controle de roles por funcao nas configuracoes

**Descricao:** O admin pode escolher quais cargos (admin, supervisor, operador) tem permissao para usar cada recurso nas configuracoes.

**Funcionamento:**
- Na secao "Administracao" do modal de configuracoes (visivel apenas para admins).
- Checkboxes por cargo ao lado de cada funcao.
- Exemplo: admin pode restringir o prefixo de mensagem apenas para supervisores e admins.
- Usuarios cujo cargo nao esta na lista permitida veem a mensagem "nao habilitado para seu cargo".

**Endpoints novos:**
- `GET /api/settings/system` — retorna configuracoes do sistema.
- `PUT /api/settings/system` — salva configuracoes do sistema (apenas admin).
- `GET /api/settings/user` — retorna configuracoes do usuario logado.
- `PUT /api/settings/user` — salva configuracoes do usuario logado.

**Arquivos alterados:** `App.tsx`, `main.py`, `database_firestore.py`

## 5. Nova Feature: Mensagens rapidas com atalhos

**Descricao:** Sistema de mensagens rapidas com atalhos customizaveis.

**Funcionamento — Usuario:**
- Em Configuracoes > "Minhas mensagens rapidas", o usuario pode criar, editar e excluir mensagens rapidas.
- Cada mensagem tem um atalho (ex: `/martelete`) e um texto completo.
- No compositor, ao digitar `/` aparece um dropdown com sugestoes filtradas.
- Ao clicar na sugestao, o texto completo substitui o atalho no campo de mensagem.

**Funcionamento — Admin:**
- Define o limite maximo de mensagens rapidas por usuario (padrao: 20).
- Pode criar mensagens rapidas globais (padrao para todos os atendentes).
- Mensagens globais aparecem nas sugestoes de todos os usuarios.
- Ideal para mensagens de inicio/finalizacao de atendimento.

**Armazenamento:**
- Mensagens do usuario: `user_settings.quick_messages[]`
- Mensagens globais + limite: `system_settings.quick_messages_global[]`, `system_settings.quick_message_max`

**Arquivos alterados:** `App.tsx`, `styles.css`, `database_firestore.py`, `main.py`

## 6. Fix: Video inline removido — download direto

**Problema:** Videos eram reproduzidos diretamente na tela do CRM, consumindo dados excessivos.

**Solucao:**
- Player de video inline substituido por um **link de download** com icone.
- O atendente baixa o video e abre no explorer/media player do sistema operacional.
- GIFs (videos leves e curtos) continuam reproduzindo inline — sao leves e nao impactam dados.

**Arquivos alterados:** `App.tsx`, `styles.css`

## 7. Fix/Feature: Flag FEATURE_MESSAGE_STATUS no .env

**Problema:** O status de mensagem (sent, delivered, read) era sempre processado e exibido, consumindo dados mesmo quando nao era necessario para a empresa.

**Solucao:**
- Nova variavel de ambiente: `FEATURE_MESSAGE_STATUS=true|false` (padrao: `true`).
- Quando `false`:
  - Webhook **nao processa** atualizacoes de status recebidas da Meta.
  - Frontend **nao exibe** o campo de status no rodape das mensagens.
- Quando `true`: comportamento atual mantido, sem alteracoes.
- Flag exposta ao frontend via endpoint `/api/client-config` → campo `feature_message_status`.

**Arquivos alterados:** `.env`, `config.py`, `webhook.py`, `main.py`, `types.ts`, `App.tsx`
